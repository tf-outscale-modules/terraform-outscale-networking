# Design

## Context

The module has no OpenSpec specs yet. Standards were kept in `agent-os/` (unversioned). The module contract is only described in the README, `TESTING.md` and the tests.

## Decisions

- **Standards come from pinned stores.** `openspec/config.yaml` references `quality`, `repository` and `terraform` at released tags (the terraform-module profile); `AGENTS.md` routes to them and keeps the non-negotiables inline. Agent OS is removed rather than ported: its content is superseded by the stores.
- **Skills for Claude Code and OpenCode.** The `openspec-*` skills are installed in `.claude/skills/` and `.opencode/skills/` (OpenCode reads `AGENTS.md` natively; `CLAUDE.md` imports it).
- **CI job `validate:specs`.** `.gitlab/specs.yml` runs `openspec validate --all --strict` with the CLI version pinned by `OPENSPEC_VERSION`, equal to the `mise.toml` pin. No store is needed in CI.
- **Capability split follows the domain files.** `module-contract` holds cross-cutting rules (tooling, inputs, tags, outputs); `core-network` follows `core.tf`, `internet-access` and `private-connectivity` split `connectivity.tf` between what faces the internet and what links Nets and Outscale services, `route-tables` follows `routing.tf` and `services` follows `services.tf`. Six capabilities keep each spec reviewable.
- **Specs describe released behaviour only.** Inconsistencies found while reading the code (reported with the change) are not specified and not fixed here.
- **CHANGELOG stays generated by git-cliff** (`mise run changelog`, `.cliff.toml`): commit subjects read as CHANGELOG lines, so the OpenSpec rules ask for a good subject instead of a hand-written entry.

## Risks

- Contributors without the stores registered cannot read the standards: `mise run spec-setup` fixes it, and `AGENTS.md` says to stop rather than guess.
